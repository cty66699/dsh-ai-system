# 配置说明 —— `_target.json` 里每个字段到底干什么

> **这是唯一的配置入口。** 所有断言脚本都从它读"要检查什么、检查哪里"。
> 不带 `--target` 时，脚本会自动采用 `example/_target.json` —— **那检查的是示例工程，不是你自己的**。

## 零、先把命令记住（本文此前**一条命令都没有**，那是最要命的缺口）

```powershell
# 换上你自己的配置后，用这条跑（在仓库根目录执行）
node checks/_check_all.cjs --fast --target <你的配置.json>

# 不带 --target = 跑作者随仓库附带的示例工程（用来确认工具本身没问题）
node checks/_check_all.cjs --fast
```

- **`--fast`**：跳过需要联网的检查（快照复查）。**建议一直带上**。
- **`<你的配置.json>`**：就是本文在讲的那个文件；**它是唯一的配置入口**。

> ⚠️ **两个必须知道的坑（实测）**：
> 1. **参数拼错会直接报错退出**（`exit 2`），**不会静默回落到示例工程** ——
>    这条是刻意的：早先版本会静默回落，于是 `--taget`（拼错一个字母）⇒ 跑示例 ⇒ `通过 9/9`、`exit 0`
>    ⇒ **接 CI 的人会得到一个永远绿灯的假绿**。
> 2. **检查器自己崩掉时，报的是「这一项崩了」，不是「有发现」** ——
>    前者说明**它根本没跑起来**（多半是你的配置指向了不存在的文件），
>    **别跑去自己的项目里找"发现"**。

## 一、先记住三条纪律（它们是行为的一部分，不是建议）

1. **未配置 ≠ 用默认。** 进入自定义目标模式后，**没配的项一律「跳过」，绝不回落默认布局**。
   理由：回落会让"你的工程"和"作者的工程"混在一起，**跑出一个假绿**。
2. **条目内的相对路径，以本文件所在目录为基准**（不是以你执行命令的目录）。
3. **扫了个空 ≠ 干净。** 扫描类脚本对 **0 个文件**判**失败**。
   ★ **"配了反而变红"不止一处**（2026-09-26 独立核验实测并更正 —— 此前这里写的是"唯一一条"，**是错的**）：
   | 你配成这样 | 会红几项 | 哪几项 |
   |---|---|---|
   | `scanDirs: []` | **2 项** | JSON 预检 · 引用检查 |
   | `publishTargets: []` | **1 项** | 发布闸门 |
   > **⇒ 想"先跳过"就别写 `[]`，直接不写那个键**（不写 = 显式跳过，写 `[]` = "我要扫，但一个对象都没有" ⇒ 判失败）。
   > `textHygieneRoots: []` 实测**不红**（它按"空即跳过"处理）—— 三个同类键的脾气**不一致**，这里如实列出来。

## 二、字段总表

**「谁在读它」与「省略后果」这两列，是逐个脚本提取 + 逐条实测得到的**，不是推断 —— 因为**推断在这里会错**（我第一版就写错了 5 处，被两个模型访客用实测揪出来）。

| 键 | 谁在读它 | 省略它的**实测**后果 |
|---|---|---|
| `declaration` | 目录符合性 / 文档漂移；**占位符检查也读它，但只要有 `product` 它仍会跑** | 目录符合性 + 文档漂移跳过；**占位符检查仍运行**（只查成品） |
| `product` | 目录符合性 / 占位符检查 | 这两项跳过 |
| `conformanceMap` | 目录符合性 | 该项跳过 |
| `dispositionManifest` | 发现处置链路 | 该项跳过 |
| `dispositionScanDirs` | 发现处置链路 | 逐条处置仍检查；仅「孤儿报告」子检查跳过，并在输出中说明 |
| `carryover` | 跨轮结转欠账 | 该项跳过 |
| `verifyBase` | 跨轮结转欠账 | ⚠️ **不跳过** —— 回落到 `repoRoot` 的解析结果 |
| `agentsDoc` / `flowDoc` / `capabilityFile` / `guide` | 文档漂移 | ⚠️ **缺任何一个 ⇒ 整项跳过**。不是"只跳一个子检查" —— 实测：删掉 `agentsDoc` 后该项报 `未配置：agentsDoc / guide ⇒ 本项跳过` |
| `register` | 文档漂移 | ✅ **真的只跳过"登记册"这一个子检查**（文档键里唯一一个） |
| `scanDirs` | JSON 预检 / 引用检查 | 这两项跳过；**`[]` ⇒ 两项都判失败** |
| `publishTargets` | 发布闸门 | 该项跳过；**`[]` ⇒ 判失败** |
| `syntaxRoots` | 语法门 | 该项跳过（`[]` 也跳过） |
| `hygieneRoots` | 文件卫生 | 该项跳过（`[]` 也跳过） |
| `convergenceLedger` + `convergenceList` | 收敛账计数 | **成对**；缺一 ⇒ 整项跳过 |
| `lessonGraduation` + `lessonDb` | 记忆毕业 | **成对**；缺一 ⇒ 整项跳过 |
| `budgetLedger` | 预算闸门 | 省略时检查运行者自己的默认账本（不存在则显示跳过）；路径会经 `--ledger` 传给预算脚本；显式 `null` 关闭 |
| `budgetPrices` | 预算闸门 | 可选价格 JSON 路径，经 `--prices` 传入；未知 provider 会返回 4，不能自动放行 |
| `repoRoot` | **所有脚本** | 回落到 `__dirname/../..` —— **未必是你的项目根**，迁移时建议显式写 |

> **★ 上表里带 ⚠️ 的条目仍需留意省略后果。**
> 它们的共同教训：**"省略一个键"的后果，取决于那个脚本怎么读它 —— 有的跳过、有的回落默认、有的是整项连坐。**
> **别按"看起来应该"来写，跑一遍。**

> **`skipBudgetCheck` 不用你写** —— 它由 `budgetLedger: null` 派生。

## 三、示例里哪些项没运行

在**无 `.git` 的干净副本**中运行 `node checks/_check_all.cjs --fast --target example/_target.json`，实测 **12 项通过、13 项跳过**（共 25 项）。跳过原因不能混为一谈：

| 原因 | 项目 | 下一步 |
|---|---|---|
| 示例没有配置（5 项） | 预算闸门、文件卫生、收敛账计数、文档漂移、记忆毕业 | 按本页字段表补齐账本、扫描目录和文档路径 |
| 公开子集未含实现（3 项） | 配置存活、验证代表性、快照复查 | 需要按自己的 DSH 环境实现，当前只会明确跳过 |
| 干净副本没有 `.git`（3 项） | 历史卫生、发布同步、提交信息 | 在 Git 仓库中运行；发布同步还取决于远端状态 |
| `--fast` 跳过慢项（2 项） | 访客视角、只读断言 | 需要时去掉 `--fast`，并注意访客视角会联网 |

示例的**语法门和 PS 语法门已运行并通过**。`node:sqlite` 的记忆毕业检查要有一份毕业账本和含教训表的 SQLite；示例没有配置这两项。

## 四、"不配置"有三种写法，含义**不一样**

| 写法 | 含义 | 结果 |
|---|---|---|
| **键不存在** | 未配置 | ⏭️ 跳过 |
| **`null`** | 显式关闭（如 `budgetLedger: null`） | ⏭️ 跳过，且**明确告诉读者这是有意关的** |
| **`[]`（空数组）** | ⚠️ **不是"跳过"** | 扫描类脚本**扫到 0 个文件 ⇒ 判失败** |
| **指向不存在的文件** | ⚠️ **未定义行为** | 别这么写 —— **宁可不配，也别留一条指向不存在文件的路径** |

## 五、路径基准：`example/` 能跑，不代表你原样复制也能跑

`_target.json` 里**条目内的相对路径以该文件所在目录为基准**。示例里 `"repoRoot": ".."` 指的是"示例目录的上一级" ——

**你若把配置原样搬到项目根目录，`..` 就指到项目外面去了。** 搬之前，把这几项按自己的布局重写一遍：

`repoRoot` · `verifyBase` · `scanDirs` · `dispositionScanDirs` · `publishTargets`

## 六、最小可用配置长什么样

**想先跑起来看效果**，配这四项就能让「目录符合性」工作：

```json
{
  "declaration": "目标声明.md",
  "product": "成品.md",
  "conformanceMap": "符合性映射.json",
  "budgetLedger": null
}
```

**⚠️ 第四项不是凑数的** —— `budgetLedger` **省略 ≠ 跳过**：脚本会去读**运行者自己机器上**的 `~/.dsh/storages/…`。**显式写 `null` 才是"关掉它"。**

**其余不配，多数 = 该项跳过**（会明确显示 ⏭️，不会假装通过）。**但有两个例外**（实测）：
- **占位符检查**：只要配了 `product`，它就会跑（它并不需要 `declaration`）；
- **预算闸门**：见上 —— **必须显式 `null` 才关**。

> ★ **别把上面这"两个例外"和 §二 表里那几处 ⚠️ 混为一谈**（2026-09-26 独立核验指出这里措辞容易误读）：
> · **"两个例外"**说的是「**不配它也照样跑**」；
> · **§二 表里的 ⚠️** 说的是「**省略它，后果不是整项跳过**」（例如 `dispositionScanDirs` 省略只跳过孤儿报告扫描，`verifyBase` 省略回落到 `repoRoot`）。
> ⇒ **两件事，两种坑。**（前者是"少配了它还跑"，后者是"少配了它乱跑"。）

**⇒ 先让它跑起来，再按需加项** —— 比一次配全再排错快得多。

预算价格可放在单独的 JSON 文件，并在 `_target.json` 写 `"budgetPrices": "价格.json"`。示例格式为 `{"my-provider/my-model":{"in":1,"cache":0.2,"out":4}}`，单位为人民币元/百万 token。脚本优先按完整 `provider/model` 查价，再回退到 provider；同一通道模型价格不同时，应逐个写全名。输入、缓存读取、输出分别按对应单价计算；缓存写入按输入价的 1.25 倍估算（需按供应商口径调整）。未计价项返回退出码 4，不能据此放行。

处置清单的严格轨道可写 `"requireEvidenceLink": true`，要求每条处置行的核对或处置栏带指向现存文件的 Markdown 链接（示例见 `example/处置清单.json`）；发现栏里的链接不算。表格必须有名称为 `处置` 的列，且该列非空；`核对`、`我的核对`等含“核对”的列可提供证据。末尾可以加备注列，脚本按表头定位，不按最后一列猜测。这只验证文件存在，**不验证链接中的内容支持裁定**。

发布闸门的 BLOCK 与 WARN 都返回 1。WARN 表示需要人工逐条判读，不能因未出现 BLOCK 自动放行；统一入口保留命中类型和位置。

统一入口也保留子检查未运行的说明；若某脚本崩溃或发生结构性错误，入口返回 2，不能按“发现问题”的 1 来判读。

发布辅助脚本 `_publish.cjs` 与发布同步检查当前限定 `origin/master`，不支持自动发布其他分支。非 master 分支会在暂存、提交之前退出 2；请使用自己的 Git 或 CI 流程。公开版不含生成器和源产物映射，“生成物陈旧”子检查明确跳过。仓库尚未附带自动触发检查的 CI workflow，接入 CI 时应自行指定必跑项与允许跳过项。

覆盖矩阵调用扫描器的 `--list-files` 模式获取实际文件选择集合。它只回答文件有没有进入至少一个扫描范围，不证明规则已经执行或足以检查该文件；各规则的执行结果仍由统一入口逐项报告。没有被选中的文件返回 1，枚举失败返回 2。

## 七、退出码约定（接 CI 用）

| 码 | 含义 |
|---|---|
| **0** | 全部实跑项通过（**跳过的项不参与判定** —— 所以"0"不等于"全都查过了"） |
| **1** | 有发现（**必须处理，或书面说明不采纳**） |
| **2** | **结构性错误**（配置解析不了、脚本起不来）—— **这不是"有发现"，是"根本没跑"** |
| **3** | 未配置 ⇒ 跳过 |
| **4** | 预算金额未知（有未计价 provider），禁止自动派发；补全价格后重跑 |

> **接 CI 前先想清楚一件事**：`0` 只说明"跑了的那些都过了"。**你要不要禁止某些项被跳过，得自己加一道判据** —— 本仓库不替你决定"哪些保障是必须的"。
