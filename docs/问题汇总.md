## 仍然不足，下一步做什么

1. **领域能力尚未得到验证。** 本仓库提供协作和检查机制，不能据此证明桥梁裂缝识别、毫米测量、缺陷漏检率或结构可靠度已经达标。下一步应使用可独立测量的试件，预先登记误差、漏检统计域和拒识条件，再收集真实数据验证。
2. **机械检查的语义能力有限。** 处置文字非空、链接存在、文件被选入扫描范围都不证明内容正确；仍需要不同模型家族或专业人员核对证据和裁定。
3. **自测还有缺口。** 16 项有反例测试不等于全覆盖；快照、配置存活和验证代表性在公开子集中没有完整实现，快速运行也跳过部分检查。剩余状态见[保障清单](保障清单.md)。
4. **预算依赖真实账本与有效价格。** 未计价时不能放行；缓存写入等估算口径需按通道校准。跨设备使用还需汇总账本，当前本机累计不能代表所有设备消费。
5. **发布警告需要人工责任人。** 当前策略为 WARN 阻止自动发布；没有提供按命中项审批的持久化豁免机制。如以后接入 CI，应先设计带证据、范围和有效期的审批记录。

建议先把这套机制用于一次小规模、有可测真值的真实交付，记录它实际拦下什么、误报什么、漏掉什么，再决定扩展哪些轨道；不要把检查项数量当成系统可信度。
