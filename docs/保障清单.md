## 二、生成公开集时的 5 道闸

| # | 闸 | 它拦什么 |
|---|---|---|
| 1 | 脱敏自检 | 产物里出现了禁忌模式（密钥 / 身份 / 客户标识 / 未发表项目名） |
| 2 | 文本完整性 | **源本来是配平的、而被脱敏替换切坏了**（反引号 / `**` / 全角括号） |
| 3 | 验收判据自检 | README 里那个自称「验收判据」的块，与它自己的汇总行对不上 |
| 4 | 模板占位符自检 | `AGENTS.template.md` 的占位符数，与 `AI-INSTALL.md` 里写的数字对不上 |
| 5 | 干净环境验证 | 把整个仓库拷到系统临时目录后跑 README 那条命令，跑不通 |

**这五道闸里有几道是「预防性」的**（写下来以备将来）：

- **文本完整性**：在当前脱敏规则表下几乎不可能触发（所有替换串的括号数都是偶数的）。
  它是**预防性**的 —— 而「预防性」最容易被人当成「没用」删掉，所以这里写明：
  **它被验证过会咬人**（临时插一条替换串含奇数括号的规则 ⇒ 它当场 `exit 2`）。

## 三、反例自检

`node checks/_selftest.cjs` —— 它往临时目录里注入已知缺陷，**要求每个断言必须变红**。

它的判据是那句话：**「注入缺陷后仍报绿 ⇒ 那不是断言，是装饰。」**

**它还会打印两件容易混起来的事**：

| 问题 | 谁回答 |
|---|---|
| **它能不能咬人？** | **反例自检**（喂一个缺陷，看它红不红）|
| **它咬到过没有？** | **拦截台账**（`_check_all.cjs` 每次真有项报红就记一行）|

> **★ 台账是你自己的**：它是**本机运行历史**，所以**公开集里没有它**（也不该有）。
> 你自己的那份会在**每次真的有项报红时**自动累积一行，存在 `checks/_拦截台账.jsonl`；
> 跑一次 `_selftest.cjs` 就能看到摘要 —— 包括「**到目前为止从没拦到过东西的有哪几项**」。
>
> **★ 看到「从没拦到过」时不要急着删它** —— 先问：**它是坏的，还是它防的事还没发生？**
> 判别方法只有一个：**主动喂它一个注定失败的输入**，看它咬不咬。

## 四、同一类错误，在不同文件类型里的**拦截厚度**（2026-09-26 加）

> **为什么要写这个**：一道护栏"存在"和"在你正在编辑的那种文件上生效"是两件事。
> 下面这张表是**实测**出来的（同一段被截断引号的文本，放进四种文件，看谁报）。
> **★ 看这张表的方法：找那些写着「没有代码语法」的行 —— 那里的护栏最薄。**

| 文件类型 | 谁能抓「字符串里嵌了半角引号」 | 厚度 |
|---|---|---|
| **`.ps1`** | ① 文本卫生（**只判奇数个引号**）② **PS 语法门**（含 **AST 判据**：相邻字符串常量且紧贴）| **两道** —— 偶数形态由 ② 抓 |
| **`.cjs` / `.js`** | **语法门**（`node --check`：引号提前结束 ⇒ 直接语法错）| **一道，但必抓** |
| **`.json`** | **JSON 预检**（`JSON.parse` 直接失败）| **一道，但必抓** |
| **`.md` 等纯文本** | **没有** —— 它没有代码语法，引号在正文里就是内容 | **★ 最薄的一层** |

**⇒ 从这张表能推出的两条实际结论**：

1. **`Markdown` 里的引号不能按代码判** —— 正文里 `他说"好"` 是正常的。
   所以**不要把代码的引号判据套到 `.md` 上**（那会大面积误报）。
   **但要知道这一点**：`.md` 里如果**嵌了代码块**，那段代码**不被任何语法门解析** ——
   这是本仓库一个**已知的、有意留下的**薄层（不是遗漏）。
2. **`.ps1` 是唯一"需要两道门"的类型** —— 因为 PowerShell 允许"引号 + 裸词"并排当多参数，
   于是"引号被切断"在那里是**合法语法**，`node --check` 那种手段抓不到；
   必须靠 **AST** 判"相邻字符串常量"才能抓到。

## 五、你实际会敲的那两个入口，各自守着什么（2026-09-26 加）

> **为什么单列一节**：上面第一节那 24 项，是**统一入口**跑的东西。
> 而你日常真正敲的是**两个入口** —— 它们自己也带守卫，**而那些守卫不在那 24 项里**。
> **⇒ 只看第一节，你会以为"护栏就是那些"** —— 漏掉这一层。

| 入口 | 守卫 | 它拦什么 | 标记串还在吗 |
|---|---|---|---|
| `node checks/_finish.cjs` | **顺序** | 改了源必然报「生成物陈旧」，**它接着生成、再复跑** —— 不让你按错顺序跑 | ✅ |
|  | **三类「不绿」分开报** | 失败 / **预期内的红** / 提醒 —— 混报会让"预期内的红"被当成失败 | ✅ |
|  | **失败即停** | 任何一步真失败就停，**不继续跑后面的**（否则后面建立在错的前提上） | ✅ |
| `node checks/_publish.cjs` | **源比产物新** | 你改了源没生成就来发布 —— 它**提醒**（不拦：只提交现有产物是合法场景） | ✅ |
|  | **要提交信息** | 没给 `--msg` 就**停下**，不生成「update」式的占位信息 | ✅ |
|  | **推送重试** | 只对**网络类**错误重试 3 次（"读取失败"和"读到了但不对"是两件事） | ✅ |
|  | **替报错澄清** | 推送失败时点明那句 `check your access rights` **常常只是网络** | ✅ |

> **★ 这张表不是手写的** —— 每条都在对应脚本里有一个**标记串**，生成公开集时逐个核对。
> **标记串不在了 ⇒ 那一行会变成 ❌** —— 于是"清单说它守着 X"这句话**不会悄悄过期**。
> （这就是它与"手写清单"的区别：手写的会漂移，**绑了标记串的会当场显形**。）



### 另一行：**BOM**（2026-09-26 实测补）

BOM 这个缺陷**危害取决于谁读它** —— 实测结果与直觉相反：

| 情形 | 实测后果 | 谁在管 |
|---|---|---|
| **`.ps1` 含非 ASCII 却无 BOM** | **PS 5.1 按 GBK 解 ⇒ 中文全乱**（实测输出 `涓枃娴嬭瘯`）| **文件卫生 H-1** |
| **`.json` 带 BOM** | **Node 的 `JSON.parse` 失败**（`Unexpected token`）；而 **PS 的 `ConvertFrom-Json` 成功** | **文本卫生（多余 BOM）** |
| **`.cjs` 带 BOM** | **Node 照跑不误**（技术上无害）—— **但它仍然该报**：BOM 会让 git diff 显示整个文件被改 | **文本卫生（多余 BOM）** |
| **`.md` / `.yaml` / `.txt` 带 BOM** | 多数解析器容忍，**但同样污染 diff** | **文本卫生（多余 BOM）** |

**⇒ 两条门的边界写在这里**（免得以后有人重复建设）：
**「缺 BOM」是 `.ps1` 独有的问题，归文件卫生的 H-1；「多 BOM」是所有文本类型的问题，归文本卫生。**

> **★ 这一行说明了一件事**：同一个缺陷（BOM）在**不同文件、被不同读者读**时，
> 后果从"完全无害"到"整个文件中文全乱"都有。**"有没有检查"是不够的信息，
> 还得知道"它在哪个条件下报、以及为什么在那个条件下报"。**
