# 产物格式 —— 七份文件各是什么、谁读它、哪儿必须对得上

> **★ 先看这里**：**每份示例文件的头部都有 `_说明` / `_纪律`（或 `_规则`）字段** ——
> **那才是格式的真正定义处**，而且它们就摆在你眼前（打开 `example/` 就能看到）。
> 本文档不重复它们，只做一件事：**把七份文件串起来** —— 谁产生、谁消费、**哪两处必须逐字对得上**。

---

## 一、数据流（一张图）

```
   目标声明 ──┐
              ├──→ 符合性映射 ──→ 【目录符合性】
   成品 ──────┘        │
     ↑                 └──→ 【占位符检查】看成品里有没有「未完成态标记」
     │ 补
     │
   裁定记录 ←──── 核验报告 ──→ 【发现处置链路】←── 处置清单（连线表）
                                    ↑
   结转账 ─────────────────────────┴──→ 【跨轮结转欠账】
```

**一句话**：**左边是"你写的"，右边是"检查它的"**，中间那层 JSON 是**把两者连起来的胶水**。

---

## 二、七份文件逐个说

### 1. 目标声明（`declaration`）

- **是什么**：要求从哪来（"要做什么"的正本）。
- **谁读它**：目录符合性 / 占位符检查 / 文档漂移（三项都读）。
- **★★ 格式是硬编码的，不是"有编号就行"** —— 这是最容易拿到**假绿**的地方：

| 段 | 解析器认的边界 | 条目要写成 |
|---|---|---|
| **§4.1** | `### 4.1` 起，到 `### 4.2` 止 | `**M1 名称**` —— **编号必须是 `M` + 数字** |
| **§4.2** | `### 4.2` 起，到 `### 4.3` 止 | **表格**，**首列**是条目名（表头行跳过） |
| **§4.3** | `### 4.3` 起，到 `---` 止 | **三列表格**：借出方 \| 借入方 \| 内容 |

  **⇒ 你的声明若解析出 0 个条目，现在会判红**（2026-09-25 修）—— 早先它会**静默通过**，
  而那意味着**"通过"了却一个要求都没对账过**。诊断信息会直接把上面这张表打给你。
  **最稳的做法：直接用 `example/目标声明.md` 当骨架改，别从空白写。**

- **另外**：**文档漂移还会检查「口径变更的影响面」那一节在不在**（示例里是 §5.1.2）——
  它的存在本身是断言要求的：**当"目标是否对题"未经外部确认时，"不对题的代价有多大"必须写在明处。**

### 2. 成品（`product`）

- **是什么**：被检查的产物本体。
- **谁读它**：目录符合性（对账）/ 占位符检查（查未完成态标记）。
- **格式要点**：无强制结构，但**它必须真的覆盖目标声明里的每一条** —— 否则目录符合性会逐条点出来。

### 3. 符合性映射（`conformanceMap`）

- **格式**：`条目名 → 检查词`。
- **⚠️ 三个坑**：
  1. **键名必须与目标声明里的条目名逐字一致**（多一个空格都算脱节）；
  2. **值是正则字符串，不是关键词** —— 例：`"M1 长尾识别引擎": "长尾|开放集|\\bOOD\\b"`；
  3. **`null` 有明确含义**：**"方向不适用，本条不对此成品对账"** —— 不是"忘了填"。
- **怎么得到正确的键**：**别手写**。跑一次目录符合性，**脚本会报出该用哪些键**。

### 4–6. 核验报告 + 裁定记录 + 处置清单 —— **这三份是一套的**

**这是整个仓库最核心的机制**：让**"发现了"** 与 **"处置了"** 之间有一条强制链路。

| 文件 | 角色 | 格式 |
|---|---|---|
| **核验报告** | **发现**从哪来 | `### R-1 ｜ 标题`（三级标题 + 编号 + 全角竖线） |
| **裁定记录** | **处置**落在哪 | 表格，每行 `\| **R-1** \| … \|` |
| **处置清单** | **把两者连起来** | `tracks[]` 里声明 `source` / `ledger` / **两个正则** |

**★ 最容易卡住的地方**：`处置清单.json` 里的**两个正则必须匹配你实际的写法**：

```json
"idPattern": "^#{3}\\s+(R-\\d+)\\s*｜",              // ← 匹配 ### R-1 ｜ 标题
"dispositionPattern": "^\\|\\s*\\*\\*{ID}\\*\\*\\s*\\|"   // ← 匹配 | **R-1** | … |
```

**你的编号格式不一样，就必须改这两个正则。** 改不对会怎样？—— **现代码会报错**（实测）：

```
⚠️ 【断言失效】示例核验：从 核验报告.md 解析出 0 条发现 —— idPattern 可能已与报告脱节
有 1 项未通过          exit = 1
```

**⇒ 它刻意把「解析出 0 条」判成「断言失效」而不是「没有发现」** —— 因为把前者当成后者，正是最危险的假绿。
（**早先的版本确实会静默全绿**；这条路径已修。**别按旧行为准备应对。**）

另外 `exempt[]` 是**禁止静默豁免**的实现：`example/` 里每个 `.md` 要么是 `source` / `ledger`，要么必须在 `exempt` 里**带上 reason**。

### 7. 结转账（`carryover`）

- **是什么**：把「本轮未做」从**记录位**变成**有强制的待办**。
- **格式**：`round`（当前轮次）+ `items[]`。
- **⚠️ 硬校验：`items` 不能是空数组** —— `{"round":1,"items":[]}` 会报 **`❌ 结构性错误：账本 items 为空`、退出码 2**。
  **⇒ 「本轮没有欠账」不能用空数组表达。** 要么**保留已完成的记录**（`done` 项留在里面），要么**干脆不配这一项**（让它跳过）。
  **不要为了凑一个非空数组去编造待办。**
- **每条 item 的字段**：

| 字段 | 说明 |
|---|---|
| `id` / `desc` | 编号与描述 |
| `opened_round` | **哪一轮开的** —— 早于当前 `round` 的条目**不许保持 `open`** |
| `status` | `open` / `done` / `waived` |
| `where` | 做在哪（人看） |
| **`verify{file, contains}`** | **`done` 必填** —— 脚本会去那个文件里**找那串文字**。**"声明完成"不算完成。** |
| **`done_round`** | ⚠️ **`done` 必填**，且必须是整数、**不能大于当前 `round`** —— 这条文档第一版漏了，是访客读源码才发现 |
| **`reason`** | ⚠️ **`waived` 必填**，且**长度 ≥ 20 字符** —— 防"不做了"三个字当理由。同上，也是访客读源码发现的 |
| **`trigger`** | **`waived` 必填** —— 必须说**什么条件下它变回必做** |

## 三、想写自己的？照这个顺序（别从空目录开始）

1. **先把 `example/` 整个目录复制走** —— 七份文件的相互引用是有讲究的，从空白开始会一直在猜；
2. 换掉 `目标声明.md`（**确保有编号的可对账清单**）；
3. 写 `成品.md`；
4. **跑一次**，**让它告诉你 `符合性映射.json` 的键该是什么**（**别手写键名**）；
5. **核验报告 / 裁定记录 / 处置清单三份一起改**（正则对不上会报【断言失效】，见 §四 第 1 条）；
6. **跑**，红了就改。**红了不是因为脚本坏，是因为有一件事真的没做。**

## 四、四个真会卡住的地方（来自作者踩过的坑）

1. **正则不匹配现在已经会报错**（`⚠️ 【断言失效】… 退出码 1`，见上一节）——
   **但"配好之后故意留一条不处置的发现、确认它真的会红"仍是必做的验收动作。**
   理由：它验的是**「处置链路真的会红」这件事本身**，而不只是"正则写对了没有"。
   **这两件事会各自出问题：正则对了但链路不会红，同样等于没有闸门。**
2. **扫描类脚本对 0 个文件判失败** ⇒ 你把 `scanDirs` 指向一个空目录，会红 —— **这不是 bug**。
3. **「没配」和「配错」长得不一样**：没配 ⇒ ⏭️ 跳过（明确说"未配置"）；配错 ⇒ 红。**别把跳过当成通过。**
4. **一份材料可以在全绿的情况下依然没答对题** —— 断言只看"字符串在不在"，**看不了"事情做没做对"**。这是最根本的已知盲区，写在这里而不是藏在脚注里。
