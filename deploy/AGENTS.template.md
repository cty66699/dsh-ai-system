## 术语（先看这个，后面才读得懂）

| 词 | 意思 |
|---|---|
| **主控** | 默认干活的那个 AI（也就是正在读这份文件的你）。**它是唯一持有完整上下文的一方。** |
| **通道 / provider** | 一个可以调的外部模型端点（如你自己的 API 服务）。 |
| **核验者** | 被派去**独立检查**某个产物的**另一个模型**。 |
| **换家族** | 核验者必须与作者**不是同一家的模型** —— 同家族复核等于没复核（实测：同一份材料两家只重叠一小部分发现）。 |
| **轨道** | 一次核验的**类型**（查事实 / 查推导 / 查一致性 / 查裁定本身 …）。 |
| **裁定** | 对"核验方报出的某一条发现"给出**结论 + 处置**。 |
| **留痕** | 把裁定写进一个**能被人读到的文件**里 —— 不写下来就等于没发生。 |
| **派发** | 把活交给外部模型去干（会**花钱**、且**不可逆**）。 |

## 一、任务难度路由

**默认由主控自己做。** 先问「主控能不能做」，只有明确不够格才升级。

| 升级判据（**这是自评标签，不是机械判据** —— 你凭它做判断，没有哪个程序会替你判）| 派发给 | provider / model |
|---|---|---|
| 〈重型编码 / 跨多文件重构 / 需最强推理攻坚〉| 〈你的强模型〉| `〈provider〉` / `〈model〉` |
| 〈短任务攻坚 / 决策性终审〉| 〈你的第二家〉| `〈provider〉` / `〈model〉` |
| 〈纯长文输出、无强推理需求、量大〉| 〈你的廉价长文模型〉| `〈provider〉` / `〈model〉` |

> **★ 填「你的强模型」时的两难（先说清，免得你踩）**：
> 你会想"哪个模型最强？"—— 但下面 §二 第 3 条**禁止你用榜单排名来定这件事**。
> **两条并存的正解是**：**先按你手上有什么填，别去查榜**；
> **等你真的有一个重型任务时，用那个任务做一次 A/B**，再回来改这一格。
> **⇒ 这一格填的是"你目前的默认选择"，不是"经过验证的结论"。**

**不升级的情形**：日常编码、文档补丁、方案撰写、资料整理、长上下文任务 —— **都是主控自己的活**。

**铁律：后台与换模型不可兼得。** 能后台的通道通常只能继承父路由；能指定模型的通道通常前台阻塞。

## 二、安全边界

> 这几条是**成本与可信度的护栏**，不是道德条款。
> **其中几条第 6/8 条来自实测踩坑；第 1/2/5 条是通用原则**（不是踩出来的，别以为每条背后都有一个故事）。

1. **主控自身的模型永不被路由** —— 不得为「更强」把主控换成高价模型。
2. **难 ≠ 贵**：成本主因是**输出量**与**缓存命中价**，不是列表单价。
3. **不许用榜单排名代替实测**：模型强弱结论必须来自**真实任务 A/B**；外部榜单只用于筛候选。
4. **升级前先说清「这次升级改变哪个决策」**；说不清就不升级。
5. **核验必须换模型家族**；作者不得兼任核验者。
   > ★ **只有一个模型怎么办**（**这条你可能会撞上，先说清**）：
   > 那样你**物理上做不了"换家族"**。此时**不要假装做到了** ——
   > **降级方案**：① 让同一个人**隔一段时间、拿着写好的判据**再查一遍（弱化版，管不了"手松"，但能抓低级错）；
   > ② **把最要紧的那几条交给外部**（哪怕只跑一次，也比"假装核验过"强）；
   > ③ **在留痕里明写「单模型，未做跨家族核验」** —— 让人知道这条产物的可信度到哪。
   > **⇒ 最坏的做法是照抄上面这句话、却没有第二个家族** —— 那会得到一个"永远亮着的红灯"。
6. **外部通道会挂**：超时、**余额耗尽**、密钥失效。派发前先确认通道可用，别假定它一定活着。
   > ★ 实测教训：失败**可能是静默的**（调用方只拿到一个 `null`，没有任何错误信息）。
   > 　 这时**怎么区分"通道挂了"与"账号没钱了"**：**换一个已知能用的端点发一次最小请求** ——
   > 　 通了 ⇒ 是原通道的问题；不通 ⇒ 更像是账号/网络层面。后者充值或换 key 即修，**换通道是过度反应**。
7. **交付物本体的数据边界**：把内容交给外部端点之前，先确认它**可以**外发。
   **核验流程本身就是一次外发，不是例外。**
8. **核验者校准**：给你用的每个核验者记一条「已知偏差」—— 它稳定误报哪一类？
   **那一类发现必须逐条反证核对，不得整包采纳。**
   > ★ **怎么记第一条**：拿它跑一两次真核验，**看它报的东西里哪一条是假的**（去原文核对），
   > 那一条就是它"已知偏差"的第一笔。**没有核验者的时候这条是空转的**（见第 0 步）。

## 三、治理规则（权力层：谁能喊停、何时喊停、喊停后谁能推翻）

> 它管的不是"怎么查"，而是"**查出来之后不许怎样**"。
> **核心命题**：真正让核验失效的通常不是"没查出问题"，而是**"查出来了没人处置"**。
>
> ★ **但这一节全部预设你已经有了核验流程、账本、断言入口。**
> **没有的话 —— 见第 0 步，只启用其中 5 条**（2/3/4/8/9），其余等你有了再开。

1. **预算熔断** —— 每次对外派发前先算一次账；过阈值就停。
   ≥〈预警值〉继续前须说清「这次派发改变哪个决策」；≥〈熔断值〉停止向外部付费通道派发。
   **恢复需用户明确同意** —— 派发是不可逆开销。
   > （**这一天还没到的话，先留空** —— 第 0 步把它排在"开始花钱派发"那一档。）
2. **质量停止权** —— 核验判「不合格」时，产物**不得进入下一步**（不得合并 / 交付 / 提交）。
   **主控无权以「我认为没问题」覆盖核验方的「不合格」**；唯一例外是走第 4 条申诉，且必须留痕。
3. **收敛规则** —— **修复 → 复核 最多 2 轮**。第 2 轮仍不合格 ⇒ **停止，上交用户**，附「两轮都失败的同一处」与两次证据。
   **不得继续循环** —— 2 轮不收敛通常说明**判据或规格错了**，不是修得不够。
   > ★ **只有你一个人（没有第二个模型）时的注意**：修复者和复核者是同一个 ⇒ **这条会变成无限循环**。
   > **降级方案**：把"复核"换成"**隔一天、对着写好的判据重看一遍**"，并且**两轮之后无条件交给人**。
4. **申诉与争议** —— 带证据的发现，**必采纳或书面说明不采纳的理由**；无证据只记录、不改产物。
   **双方都有证据且结论冲突 ⇒ 上交用户。主控不得以身份压过核验者。**
5. **复核链终止条件**（解无限回归）—— **最多两层**：主控裁定 → 复核裁定。**复核的产出不递归。**
6. **强制盲评与判据预注册** —— 主控既是产物作者、又是判分者时：**先写判据、后看产物**；**判分时隐藏来源标签**。
   > **诚实边界**：盲评能治好「看见是谁写的就手松」，**治不好**规格权/判据权/判分权三权合一。
7. **统一检查入口** —— 交付前 / 收尾时跑一次**你能配的那几项**：
   ```powershell
   # 在仓库根目录执行。不带 --target 会跑作者随附的示例工程（用来确认工具本身没问题）
   node checks/_check_all.cjs --fast --target example/_target.json
   ```
   > **★ 三个必须一起记住的事**：
   > ① **这条命令跑的是示例工程，不是你的项目** —— 要检查你自己的，得先写一份配置（见 `docs/配置说明.md`）；
   > ② **输出里的 `⏭️ 跳过` ≠ 通过** —— 它等于"**这一项没查**"。示例配置下**跳过 8 项、只跑 10 项**；
   > ③ **`--fast` 建议一直带着**；**参数拼错会直接报错**（不会静默回落到示例）。
8. **发现必须逐条处置** —— 核验方报出的**每一条**发现，必须在裁定记录里**单独有一行**处置。
   **批量合并、范围缩写、「待逐条补证据」都不算处置。禁止静默豁免。**
9. **跨轮欠账必须做掉或书面豁免** —— 「本轮未做」的事项必须在下一轮变成 done 或 waived；
   **waived 必须带 reason + trigger**（什么时候会重新变成必做）。**不许以 open 状态跨轮躺着。**
   > ★ 另有一条同族的坑：**凡「全局计数器 + 严格相等」这种牙齿，先问「写进这个计数器的，是不是只有我」** ——
   > 　 如果不是（比如多个会话共享一个工作区），它就会**把别人的行为算成你的失职**，
   > 　 而两种"修绿"的方式（**替人处理** / **上调阈值**）**都会让这个计数器失去意义**。
10. **记忆毕业制** —— **lesson 是候选态，不是终点。**
    每条写下来的教训必须有一个归宿：**能被一段代码拦下 ⇒ 当天转成断言**（且必须真的在每次检查里跑）；
    不能 ⇒ 写明「**只能靠外部复核**」并指明由谁复核。**第二次复发 = 禁止再写第 N 条 lesson**。
    > **依据**：实测过一个反例 —— 同一类错误，写成 lesson 之后**照样再犯**；写进本文件（每会话注入）**也犯**；
    > 写成断言进统一入口之后，**是脚本自己抓到的**。
    > ⇒ **记忆管「我想什么」，断言管「我做什么」，换家族复核管「我做得对不对」。三者混用就会出现"记着、但照样错"。**
